BR3 - rule verification (RED)
=================================

WHAT THIS IS
------------
A behavioural RED for BR3: "Within one Show, a ShowSeat may be allocated to
at most one Reservation."

It was produced by temporarily deleting the invariant guard from
Show.reserve_seat() and re-running the BR3 tests. The guard was restored
immediately afterwards and is present in the current code and in git history.

It answers the question "do these tests actually have teeth?" - if the rule is
removed from the code, does a test notice? Here it does: the test fails with
DID NOT RAISE SeatAlreadyReservedError, which is the exact behaviour BR3
forbids.

HONESTY NOTE
------------
This is NOT the original TDD history. It is a verification run captured on
2026-10-05 against the finished code, and it is labelled that way on purpose.

The original RED for BR3 is br3_red.txt. That one is weaker: it only records
ModuleNotFoundError, which proves the module was absent. It does not prove any
assertion about BR3 behaviour would have failed. A RED that dies at import
time has not yet expressed the rule.

WHY BOTH ARE KEPT
-----------------
Both are shown in the presentation, and the difference between them is the
point: a RED has to fail on behaviour, not on a missing file.
