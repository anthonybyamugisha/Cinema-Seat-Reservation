BR4 - rule verification (RED)
=================================

WHAT THIS IS
------------
A behavioural RED for BR4: "A Reservation is eligible only when the Show has
not started and the customer has fewer than four confirmed seats for that
Show."

It was produced by temporarily disabling the four-seat limit in
ReservationEligibilityService.check_eligibility() and re-running the BR4 tests.
The limit was restored immediately afterwards and is present in the current
code and in git history.

It answers the question "do these tests actually have teeth?" - if the rule is
removed from the code, does a test notice? Here it does: the boundary test
that a customer holding exactly four seats is rejected fails with
DID NOT RAISE ReservationNotEligibleError.

The other six BR4 tests keep passing, which is the useful part: they isolate
the seat-count rule specifically, so the failure points straight at the guard
that was removed instead of failing everywhere at once.

HONESTY NOTE
------------
This is NOT the original TDD history. It is a verification run captured on
2026-10-05 against the finished code, and it is labelled that way on purpose.

The original RED for BR4 is br4_red.txt, which only records
ModuleNotFoundError. That proves the module was absent, not that BR4 had any
behaviour asserted against it.
